# Role & Objective

You are a senior software engineer tasked with fixing a regression bug in a knapsack solver project and performing comprehensive validation of the fixed implementation.

# Inputs & Context

**Project Structure:**
- Original buggy project located at: `issue_project/`
- Detailed bug documentation in: `issue_project/KNOWN_ISSUE.md`
- Repair instructions in: `REPAIR_PROMPT.md`
- Source code: `src/knapsack_solver.py` (contains validation regression on line 29)
- Test suite: `tests/test_knapsack_solver.py`

**Bug Summary:**
- Type: Regression bug with inverted input validation logic
- Location: Line 29 in `src/knapsack_solver.py`
- Impact: All normal inputs with positive weights incorrectly return 0
- Current state: 4 test failures, 2 passes

# Step-by-Step Instructions

## Phase 1: Analysis & Setup

1. Read and analyze `KNOWN_ISSUE.md` to understand the root cause of the regression bug
2. Review the buggy implementation in `src/knapsack_solver.py`
3. Examine all test cases in `tests/test_knapsack_solver.py` to understand expected behavior
4. Create a new directory `issue_project_fixed/` as a sibling to the original `issue_project/` directory

## Phase 2: Implementation of Fix

1. Copy the entire project structure from `issue_project/` to `issue_project_fixed/`:
   - `src/__init__.py`
   - `src/knapsack_solver.py`
   - `tests/__init__.py`
   - `tests/test_knapsack_solver.py`
   - `README.md`
   - `requirements.txt`
   - Optionally: `KNOWN_ISSUE.md` (for reference)

2. Apply the minimal fix to `issue_project_fixed/src/knapsack_solver.py`:
   - Locate the inverted validation logic (approximately line 29-32)
   - Change from: `if any(w > 0 for w in weights): return 0`
   - Change to: `if any(w <= 0 for w in weights): return 0`
   - This single-line change corrects the validation to properly reject non-positive weights

3. Ensure the dynamic programming implementation returns mathematically optimal solutions

4. If test expectations do not match mathematically optimal results, update test assertions in `issue_project_fixed/tests/test_knapsack_solver.py` to reflect correct optimal values (e.g., change expected value from 10 to 13 for basic_example test)

## Phase 3: Documentation

1. Create `issue_project_fixed/FIX_SUMMARY.md` containing:
   - Exact changes made (specific file and line numbers)
   - Explanation of why the change fixes the regression
   - Test results showing all tests passing
   - Verification steps performed

2. Update `issue_project_fixed/README.md`:
   - Remove any warnings about known bugs
   - Update test results section to show all tests passing
   - Add a "Fixed Issues" section documenting the regression fix

## Phase 4: Comprehensive Validation

### 4.1 Environment Setup
1. Configure Python environment for the fixed project
2. Create and activate a virtual environment if needed
3. Install all dependencies from `requirements.txt`:
   - Install pytest (pytest>=7.4.0)
   - Verify Python version compatibility (Python 3.12+ recommended)

### 4.2 Execute Full Test Suite
1. **Run unittest framework:**
   ```bash
   cd issue_project_fixed
   python -m unittest discover tests -v
   ```
   - Capture complete output including execution time
   - Verify all 7 tests pass (100% pass rate)

2. **Run pytest framework:**
   ```bash
   python -m pytest tests/ -v
   ```
   - Cross-verify results with unittest
   - Capture detailed test output

### 4.3 System Launch Verification
1. Verify the solver module can be imported without errors:
   ```python

   ```
2. Test basic functionality with sample inputs
3. Ensure no runtime errors, exceptions, or warnings

### 4.4 Manual Functional Validation
Create validation scripts to test:
1. **Basic usage test:**
   - Capacity: 10, Weights: [2,3,4,5], Values: [3,4,5,6]
   - Expected output: 13

2. **Edge case validation:**
   - Zero capacity scenarios
   - Empty item lists
   - Single item scenarios
   - Classic knapsack examples
   - Large capacity tests

3. **Syntax and code quality checks:**
   - Run `python -m py_compile src/knapsack_solver.py`
   - Run `python -m tabnanny` for indentation verification

### 4.5 Capture and Document
1. Record all test outputs (unittest, pytest, manual tests)
2. Capture execution times and performance metrics
3. Document system behavior under all test scenarios
4. Note any warnings, edge cases, or behavioral observations

### 4.6 Validation Summary
Create a comprehensive validation report stating:

- Explicit confirmation: "All test cases passed: YES/NO"

- Environment details (Python version, pytest version)
- Any discrepancies or issues encountered
