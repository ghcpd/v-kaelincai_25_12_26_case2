# Role & Objective

You are a senior software engineer tasked with fixing a regression bug in a knapsack solver project and performing comprehensive validation of the fixed implementation using multiple testing frameworks and runtime verification.

# Inputs & Context

**Project Structure:**
- Original buggy project located at: `issue_project/`
- Detailed bug documentation in: `issue_project/KNOWN_ISSUE.md`
- Repair instructions in: `REPAIR_PROMPT.md`
- Source code: `src/knapsack_solver.py` (contains validation regression on line 29)
- Test suite: `tests/test_knapsack_solver.py`

**Bug Summary:**
- Type: Regression bug with inverted input validation logic
- Location: Line 29 in `src/knapsack_solver.py`
- Impact: All normal inputs with positive weights incorrectly return 0
- Current state: 4 test failures, 2 passes

# Step-by-Step Instructions

## Phase 1: Analysis & Setup

1. Read and analyze `KNOWN_ISSUE.md` to understand the root cause of the regression bug
2. Review the buggy implementation in `src/knapsack_solver.py`
3. Examine all test cases in `tests/test_knapsack_solver.py` to understand expected behavior
4. Create a new directory `issue_project_fixed/` as a sibling to the original `issue_project/` directory

## Phase 2: Implementation of Fix

1. Copy the entire project structure from `issue_project/` to `issue_project_fixed/`:
   - `src/__init__.py`
   - `src/knapsack_solver.py`
   - `tests/__init__.py`
   - `tests/test_knapsack_solver.py`
   - `README.md`
   - `requirements.txt`

2. Apply the minimal fix to `issue_project_fixed/src/knapsack_solver.py`:
   - Locate the inverted validation logic (approximately line 29-32)
   - Change from: `if any(w > 0 for w in weights): return 0`
   - Change to: `if any(w <= 0 for w in weights): return 0`
   - This single-line change corrects the validation to properly reject non-positive weights

3. Verify the fix produces mathematically correct results:
   - The DP algorithm should now return optimal values
   - For capacity=10, weights=[2,3,4,5], values=[3,4,5,6], the optimal is 13 (not 10)

4. **CRITICAL: Update test expectations to match mathematical correctness**
   - After fixing the validation bug, some test assertions may expect incorrect values
   - Update test assertions in `issue_project_fixed/tests/test_knapsack_solver.py` where needed
   - Specifically: `test_basic_example` and `test_basic_with_items` should expect 13 (not 10)
   - This correction is REQUIRED for tests to pass after fixing the validation bug

## Phase 3: Documentation

1. Create `issue_project_fixed/FIX_SUMMARY.md` containing:
   - Exact changes made (specific file and line numbers)
   - Explanation of why the change fixes the regression
   - Documentation of test expectation corrections (if any)
   - Test results showing all tests passing from multiple frameworks
   - Verification steps performed

2. Update `issue_project_fixed/README.md`:
